# Dependency locking

The project declares supported dependency ranges in `requirements.txt` and the full project metadata in `pyproject.toml`.

Connected CI resolves the dependency graph with `uv lock` and verifies it with `uv lock --check`. The audit environment used for the v4.2.0 build had DNS/network access disabled and did not have several runtime dependencies installed, so generating a truthful lockfile locally was impossible. Rather than commit a fabricated or incomplete lockfile, v4.2.0 leaves lockfile generation to the connected CI/release environment.

For a connected release environment:

```bash
uv lock
uv lock --check
uv sync --frozen
python scripts/smoke_test.py
python scripts/validate_release.py
```

Once `uv.lock` is generated by that connected environment, it should be committed and the `dependency-lock` CI job will enforce that it remains consistent with `pyproject.toml`.
